# SOMETHING 中国大陆上架预审

更新：2026-11-13  
依据：工信部信管〔2023〕105 号《关于开展移动互联网应用程序备案工作的通知》、App Store Connect 中国大陆可用性要求，以及当前仓库实际代码。  
性质：工程与产品预审，不替代律师、通信管理局或 Apple 的正式判断。

## 核心判断

**当前版本如果只面向海外、香港、澳门和台湾发行，不需要为了现有功能立即办理中国大陆 App 备案。**

**一旦开放中国大陆 App Store，App 备案就是上架流程的硬门槛。** 触发备案的核心是“通过 App 向中国大陆用户提供互联网信息服务并在中国大陆应用商店分发”，不是健身、语音提醒或本地记录中的某一个功能。

从当前代码看：

- 没有账号系统；
- 没有后端 API、CloudKit 或远程同步；
- 没有公开社区、评论、直播、新闻或用户内容分发；
- 没有广告、第三方分析 SDK；
- 没有 App 外支付或自有支付；
- 没有在线生成式 AI；
- 健康与训练数据按架构红线只保存在本机。

所以当前不存在一个独立功能，使产品必然被认定为医疗诊断软件、互联网新闻服务、网络文化产品、在线交易平台或社交平台。

## 一定会阻碍中国大陆上架的项目

| 项目 | 当前状态 | 结论 |
| --- | --- | --- |
| App 备案号 | 未办理 | 开放中国大陆前必须补齐 |
| 可备案主体 | 尚未确定个人或企业路径 | 备案主体需与域名、资料和责任主体一致 |
| 可备案域名 | 当前使用 `acanxp-cyber.github.io` | GitHub Pages 不能直接作为中国大陆 App 备案域名 |
| 隐私政策与支持页 | GitHub Pages | 大陆发行时建议迁到备案域名下的稳定页面 |
| App 实际功能说明 | 现有说明未覆盖语音、健身和闹钟 | 备案和审核说明必须与当前版本一致 |

这些是上架材料问题，不是代码中存在违法内容。

## 当前功能逐项审查

| 功能 | 是否本身触发额外备案/资质 | 主要审核点 |
| --- | --- | --- |
| 本地任务、文字记录、周回顾 | 否 | 隐私、数据导出和删除说明 |
| 本机中文语音识别 | 否 | 麦克风和语音识别权限用途必须明确；录音不保存、不上传 |
| iOS 26 AlarmKit 系统闹钟 | 否 | 闹钟授权用途必须明确；旧系统只能回退普通通知 |
| 50 个徒手训练动作 | 否 | 必须保持一般健身建议，不能声称诊断、治疗或康复 |
| 按上肢/下肢/核心等推荐训练 | 否 | 推荐逻辑应可解释；首次使用应有安全提示 |
| 训练任务提醒 | 否 | 与普通任务提醒同一隐私边界 |
| 本地 JSON 导出 | 否 | 导出文件由用户主动触发，开发者不接收 |
| ¥1 付费下载 | 否 | 由 Apple 处理交易，不建设站内第三方支付 |
| GitHub Pages 隐私/支持链接 | 会增加大陆审核不确定性 | 大陆发行时改用备案域名 |

## 什么情况会从“备案问题”升级为“额外资质或审核风险”

以下功能当前没有，后续加入前必须单独评估：

1. **医疗化训练建议**
   - 疾病诊断、疾病风险预测、康复处方、用药建议、根据心率或疾病给出治疗结论。
   - 这类功能可能进入医疗器械、互联网医疗或医疗广告审查范围。
2. **用户账号、云同步和远程存储**
   - 需要重新做隐私政策、数据分类、账号注销、数据出境和网络安全评估。
   - 个人健康、训练与身体数据不能因为“普通同步功能”被顺带上云。
3. **社区、评论、公开分享或排行榜**
   - 会引入用户生成内容治理、内容审核、举报和未成年人保护要求。
4. **资讯、课程商店或付费内容平台**
   - 可能触发互联网信息服务、网络文化或出版相关判断。
5. **在线 AI 教练或远程模型**
   - 需要披露数据是否离开设备、第三方处理方、生成内容标识及健康建议边界。
6. **App 外支付引导**
   - 除备案外还会直接触发 Apple 审核风险。

## 健身文案红线

当前训练模块必须保持以下口径：

- 可以说“一般健身建议”“动作调整”“强度降低”；
- 不可以说“治疗腰痛”“矫正疾病”“康复处方”“根据症状判断病因”；
- 不可以根据用户伤病自动给出诊断或替代医生；
- 出现疼痛、伤病或身体不适时，应停止并建议咨询医生或合格教练；
- 不把训练推荐描述成保证减重、增肌、疗愈或疾病改善。

当前代码已经加入一般健身免责声明，符合这条边界。

## 中国大陆发行前的最小清单

- [ ] 明确使用个人还是企业主体备案
- [ ] 准备中国大陆可备案域名
- [ ] 将隐私政策、支持页迁到该域名
- [ ] 完成 App 备案并取得 App 备案号
- [ ] 在 App Store Connect 填写备案号
- [ ] 更新 App 描述：加入语音、健身、系统闹钟和本地存储说明
- [ ] 确认麦克风、语音识别、闹钟和通知权限文案
- [ ] 确认训练内容不涉及诊断、治疗、康复处方或用药建议
- [ ] 确认健康、训练、语音内容不进入 CloudKit、iCloud 或远程日志
- [ ] 用大陆网络环境完成一次隐私页、支持页和 App 下载验证

## 最终结论

**当前功能不需要额外的医疗、新闻、文化或交易牌照；开放中国大陆发行时，App 备案不能被省略。**

首版继续排除中国大陆是当前最稳妥方案。若决定进入中国大陆，先解决主体、域名和备案号，再提交大陆版本；代码功能本身不需要为了备案删除健身或闹钟。
